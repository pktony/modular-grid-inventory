  • 포함: 보관함·가방·분할 리그 간 이동·회전, 중첩 탐색, 구획별 배치·수납 제한, 스택 합치기·분할, 샘플 정의 10종.

  • 제외: 전투·상점·퀘스트·네트워크, 무기 부착·탄창 장전, 소모품 사용 효과, 저장·불러오기, 임의 형태의 구획.

03

데이터·책임·구획·변경 흐름

정의책임·필드
ItemCategoryDefinition고정 ID·이름·부모 분류; 단일 부모 트리, 하위 분류 추가 가능
ItemDefinition고정 ID·이름·분류·외부 크기·아이콘·최대 스택·선택적 컨테이너 정의 참조
ContainerDefinition구획 정의 목록·공통 수납 정책; 가방 외부 크기와 구획별 내부 크기 분리
GridSectionDefinition컨테이너 내부의 고정 구획 ID·격자 크기·선택적 수납 정책
ContainerLayoutDefinition구획 ID별 화면 표시 위치·순서·간격; 배치 규칙과 분리
ContainerAcceptancePolicy전체 허용/목록 허용 모드, 허용·금지 분류, 개별 아이템 허용·금지 ID
ItemCatalog정의 목록과 에디터 표의 입력; 표 편집은 해당 SO에 반영, 런타임은 검증된 정의 사용
  • 같은 종류의 아이템·가방은 정의 SO만 공유; 수량·내용물·소속·좌표·회전은 정의에 저장하지 않는다.
  • 초기 분류: Weapon/AssaultRifle, Consumable/Medical/Medkit, Consumable/Food, Consumable/Drink, Ammo/9x19, Ammo/5.45x39, WeaponPart/Foregrip, Container/Backpack, Container/Case, Container/Rig.
  • 분류는 의미, 컨테이너 기능·스택 상한은 구성 데이터로 표현; 기능마다 아이템 상속 클래스를 늘리지 않는다.
  • 상위 분류는 자손에 적용, 금지는 허용보다 우선; 목록 허용 모드의 빈 목록은 거절, 전체 허용 모드는 금지만 적용한다.
  • 수납 검사는 바로 넣는 아이템을 대상으로 한다; 내부 아이템은 해당 가방의 정책을 따른다.
  • 가방별 정책으로 가방 자체도 허용·금지 가능; 정책 통과 후에도 외부 크기가 실제 빈 공간에 맞아야 한다.
  • 크기·스택 상한은 1 이상, 컨테이너 상한은 1; 표 저장·검증 후 초기화에 적용, 잘못된 카탈로그로 시작 거절.

InventoryUIFactory / InventoryUI각각 화면 구성요소 생성 / 주입받은 구성요소로 표시·입력 이벤트 전달
Inventory구성요소 생성·의존성 연결·수명 정리
  • SOLID(책임 분리·확장·치환·인터페이스 분리·의존성 역전) 준수; SRP(단일 책임 원칙)는 예외 없이 적용, 제약에만 짧은 주석.
  • 적용: Factory는 생성, MVP(Model–View–Presenter)는 입력·표시 분리, Composition Root는 의존성 조립, Observer는 확정 후 알림.
  • 요청은 ID 기반 불변 Command 형태, 반영은 트랜잭션 형태의 변경 묶음; Undo·이벤트 소싱·별도 조회 저장소·전역 이벤트 버스 제외.
  • 수납은 데이터와 순수 평가기로 처리; 교체할 알고리즘이 생길 때만 Strategy 적용, 모든 규칙을 인터페이스화하지 않는다.
  • 중첩은 객체 구성·ID 트리로 표현; Composite 필수 적용 제외, 일반 아이템·리그 구획에 가방 기능을 강제하지 않는다.

공개 인터페이스와 내부 변경 경계

공개 계약이용자·허용 작업
IItemCatalog서비스·UI의 불변 정의 뷰 조회
IInventoryReadModelUI·입력의 컨테이너·아이템·배치 스냅샷 조회와 확정 후 변경 알림
IInventoryTransferService입력의 같은/다른 컨테이너 이동·회전 요청
IInventoryStackService입력의 합치기·분할 요청
IInventoryEditService입력·데모의 추가·삭제 요청
  • UI와 컨트롤러는 조회 결과와 변경 서비스만 사용; 가변 딕셔너리·런타임 객체·setter를 공개하지 않는다.
  • 조회는 불변 스냅샷과 ID를 반환; 읽기 전용 컬렉션 안에 수정 가능한 객체를 담아 노출하지 않는다.
  • 카탈로그는 초기화 시 SO를 불변 정의 뷰로 복사·공유; 배열과 요소도 수정 불가, UI에 SO 원본·편집 API 비노출.
  • 명령은 ID·대상 컨테이너·좌표·회전·필요 수량만 전달; 결과는 성공 여부·실패 이유·실제 이동 수량을 반환한다.
  • DefinitionId·ItemInstanceId·ContainerId·GridSectionId를 구분; 구획 ID는 소속 컨테이너 안에서 식별한다.
  • 모델과 UI의 Assembly Definition(asmdef)을 분리; UI는 공개 계약만 참조, 가변 상태·확정 API는 모델 어셈블리 내부에 제한.
  • 구성 루트가 서비스·조회·뷰 Factory를 주입; 입력은 구독 계약, 좌표는 대상 판별, 뷰는 표시 계약으로 분리.
  • 구현 시작 순서: 정의 계약 → ItemInstance·배치 소유권 → 조회/변경 계약과 확정 경로 → 가방 UI → 스택 UI.

인스턴스 소유권과 수명

  • 가방 인스턴스 → 고유 내부 컨테이너 → 배치된 아이템 ID로 연결; Berkut 두 개는 같은 정의와 서로 다른 내부 컨테이너를 갖는다.
  • 소속·구획·좌표·회전은 배치만 소유; 인스턴스에는 중복 저장하지 않고 인덱스·점유는 배치에서 동기화한다.
  • 추가·분할·삭제·초기화의 등록/제거·인덱스 교체도 공통 확정 경로만 사용; Factory·Session·Registry의 독립 변경 경로 금지.
  • 가방 이동은 외부 배치만 변경; 내부 컨테이너와 자손 인스턴스를 다시 생성하지 않는다.
  • 초기화는 드래그 취소·이전 세션 구독 해제·전체 상태 교체·뷰 재연결 순서; Dispose 시 구독과 세션 참조 해제.

정의는 공유 · 내부 컨테이너는 개별 소유

여러 구획의 컨테이너

  • 리그 하나는 하나의 ContainerId와 여러 GridSectionId를 갖는다; 구획에는 아이템 인스턴스·중첩 경로를 만들지 않는다.
  • 보관함·일반 가방은 구획 1개, 리그는 구획 여러 개로 같은 계약을 사용; 구획은 직사각형 격자로 한정한다.
  • 아이템은 한 구획 안에 완전히 들어가야 한다; 구획이 화면에서 붙어 있어도 경계를 걸쳐 배치할 수 없다.
  • 빈 칸 총합이 충분해도 어느 구획에도 맞지 않으면 실패; 자동 배치는 구획별 후보를 검사한다.
  • 컨테이너 공통 정책과 구획 정책을 모두 만족해야 수납 가능; 구획 정책은 공통 금지를 해제하지 못한다.
  • 입력·미리보기·명령은 (ContainerId, GridSectionId, Cell)로 지정; 화면 오프셋은 UI에서만 좌표 변환에 사용한다.
  • 같은 컨테이너의 구획 간 이동·합치기는 해당 상태를 한 번 확정·알림; 소속은 유지하고 배치 구획만 변경한다.
  • 순환 검사는 컨테이너/가방 관계만 순회; 가방이 어느 구획에 있어도 내부 컨테이너와 내용물은 유지한다.

한 컨테이너 안의 독립 격자

최신 상태 검증 → 다음 상태 준비 → Committer의 단일 교체 → Publisher의 알림 → 영향받은 Presenter 갱신. 준비 실패는 원본을 유지하고, 알림 실패는 확정 성공을 유지합니다.

항상 유지해야 하는 조건

  • 확정된 아이템 ID는 정확히 한 컨테이너의 한 구획에 속함; 다른 컨테이너에 같은 인스턴스 등록 거절, 회전·점유 일치.
  • 가방을 옮겨도 내부 컨테이너 ID와 모든 내용물 ID·배치·수량은 유지한다.
  • 중첩 깊이를 고정 제한하지 않는다; 방문 ID 검사로 순환 방지, UI는 현재 가방 하나만 표시한다.
  • 미리보기는 원본 불변; 서비스가 최신 상태로 재검증해 아이템·양쪽 컨테이너·점유·인덱스를 포함한 다음 상태를 준비한다.
  • 준비 중 예외·검증 실패·Esc·영역 밖 드롭은 전체 불변; Committer가 준비된 상태를 단일 교체한 뒤 Publisher에 알림 위임.
  • 확정·알림 중 재진입 요청 거절, 보호 상태는 finally로 해제; 콜백 예외는 기록·격리하고 나머지 구독자에게 계속 알림.
  • 알림 오류는 확정 성공을 실패로 바꾸거나 롤백하지 않음; 확정당 변경 배치 1회, 영향받은 컨테이너·아이템 ID와 버전 전달.
  • 내용물 있는 가방의 Delete는 거절하고 비우기 안내; 빈 가방 삭제 시 내부 컨테이너도 정리, 초기화는 전체 트리 재생성.
  • 스택은 동일 정의 ID만 합친다; 최대 상한을 채우고 잔량은 원래 칸에 유지, 이동량 0이면 실패 안내.
  • 합치기는 빈 공간을 자동 탐색하지 않는다; 다른 종류 아이템 위 드롭은 실패, 자동 교환 제외.
  • 수량 0이 된 원본 스택은 제거하고 점유 해제; 존재하는 스택 수량은 항상 1..MaxStack.
  • 분할은 1..현재 수량-1; 새 ID를 만들고 빈 칸 드롭 성공 시 원본 수량 차감, 취소 시 아무 변화 없음.
  • 사용 횟수·내구도와 스택 수량을 구분한다; 의료품 효과·남은 사용량 구현은 범위 밖이다.

검증·시연 완료 기준

  • 데이터: 분류 3단계·부모 허용/자손 금지·아이템 예외·빈 허용 목록·중복 ID·분류 순환·누락 참조·잘못된 크기/상한.
  • 모델: 3단계 가방·자기/조상 순환·공간 부족·내용물 있는 가방 이동/삭제·동일 정의 내용 독립; 중복 인스턴스 등록 거절·한쪽 회전 후 타 컨테이너 불변.
  • 구획: 구획 ID 중복/누락, 경계 걸침·구획 사이 드롭 거절, 총빈칸 대비 단일 구획 부족, 회전 후 적합, 공통/구획 정책 교집합·구획 간 이동/합치기.
  • 서비스: 컨테이너 간 성공/실패·드롭 재검증·수량/ID/점유 일치; 준비 예외 시 전체 불변; 콜백의 상태 완결·예외 격리·성공 유지·후속 알림·보호 해제.
  • 계약·수명: UI 가변 상태 접근 불가·SO/배열 수정 후 기존 정의 불변·실패/취소 시 미소속 인스턴스 없음·알림 중 재진입 거절·초기화 구독 해제.
  • 스택: 상한 1/50/60, 동일 구경 다른 정의 거절, 40+20→50+10, 완전 합치기, 가득 찬 스택, 분할 0/전량 거절·취소.
  • UI: 1280×720·1920×1080·패널별 스크롤·반복 탐색/초기화 뒤 리스너 중복 없음·이동 뒤 경로 갱신; 드래그 중 전체 목록 재표시/스냅샷 복사 없음.
  • 시연: 가방 열기 → 중첩 탐색 → 내용물 유지 이동 → 전용 케이스 거절 → 스택 합치기·분할 → 회전·취소 → SO 설정 표.
  • 최종 통과: 기존 20개 테스트와 추가 규칙·통합 테스트, Windows 직접 입력 시나리오, 이미지·문서·영상 완비.
